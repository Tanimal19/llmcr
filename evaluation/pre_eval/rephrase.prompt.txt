You are creating pseudo-reference statements for pull request evaluation.

Given a pull request title, description, and discussion comments, generate a strict JSON object:

}

Requirements:
1. Extract and rewrite only meaningful technical claims, decisions, requirements, issues, fixes, risks, limitations, design rationales, and implementation details.
2. Each sentence must express exactly one atomic idea.
   - Split compound statements into separate sentences.
   - Avoid conjunction-heavy sentences.
3. Preserve technical meaning precisely.
   - Do not introduce assumptions.
   - Do not infer behavior that is not explicitly stated.
4. Remove redundancy.
   - Merge paraphrases describing the same technical point.
   - Keep the clearest and most informative version.
5. Prefer concrete and review-relevant statements.
   - Include implementation changes.
   - Include identified bugs.
   - Include edge cases.
   - Include performance, security, compatibility, reliability, or maintainability concerns.
   - Include architectural decisions and tradeoffs.
6. Exclude low-value content:
   - greetings
   - thanks
   - approvals
   - process discussions
   - release management
   - merge/rebase discussions
   - review logistics
   - status updates without technical content
7. Rewrite statements into standalone sentences.
   - The sentence should remain understandable without PR context.
   - Replace vague references such as "this", "it", "that change", or "the above" with explicit subjects.
8. Retain important entities when relevant:
   - class names
   - methods
   - APIs
   - configuration keys
   - files
   - database tables
   - protocols
9. Prefer declarative factual statements over opinions.
10. Keep the original language of the source content.
11. Output only valid JSON. Do not include markdown fences. Do not include explanations.
